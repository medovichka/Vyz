\section*{Цель работы}
\addcontentsline{toc}{section}{Цель работы}
Разработка веб-приложения на языке Java с использованием фреймворка Spring Boot, Hibernate и реляционной базы данных PostgreSQL для хранения информации об организациях и сотрудниках с демонстрацией принципов объектно-ориентированного программирования.

\section*{Задание}
\addcontentsline{toc}{section}{Задание}

На основании согласованной в первой и второй лабораторной работе предметной области разработать приложение на языке Java, удовлетворяющее следующим требованиям:
\begin{enumerate}
    \item Использование СУБД PostgreSQL.
    \item Использование сборщика Maven (все зависимости подключаются через Maven).
    \item Использование Hibernate для доступа к БД (работа с сущностями, никаких SQL-запросов вручную).
    \item База данных должна содержать не менее трёх связанных таблиц, находящихся в третьей нормальной форме. Обязательно наличие хотя бы одной связи, отличной от наследования (один ко многим или многие ко многим через таблицу-связку).
    \item Разметка модели осуществляется через аннотации (можно использовать Lombok для сокращения кода).
    \item Реализован веб интерфейс.
    \item Для CRUD-операций используется интерфейс CrudRepository из пакета org.springframework.data.repository.
\end{enumerate}

\subsection*{Веб контроллер}
\addcontentsline{toc}{subsection}{Веб контроллер}

Класс `ru.university.lab3.controller.WebController` обрабатывает HTTP-запросы от пользователя. Он использует аннотации Spring Framework для определения своей роли и для привязки методов к конкретным URL-адресам.

\textbf{Ключевые аннотации Spring в контроллере:}
\begin{itemize}
    \item \textbf{@Controller}: Помечает класс как контроллер в архитектуре Spring MVC, который отвечает за обработку входящих веб-запросов и возврат представлений (HTML-страниц).
    \item \textbf{@Autowired}: Используется для автоматического внедрения зависимостей. В данном проекте эта аннотация внедряет экземпляры репозиториев (`OrganizationRep`, `EmployeesRep` и др.) в контроллер, что позволяет ему взаимодействовать с базой данных.
    \item \textbf{@GetMapping} и \textbf{@PostMapping}: Привязывают HTTP-методы GET и POST к методам контроллера. Например, `@GetMapping("/")` означает, что метод будет вызван при GET-запросе на главную страницу сайта. `@PostMapping("/addComOrg")` означает, что метод обработает данные, отправленные из формы добавления коммерческой организации.
    \item \textbf{@RequestParam}: Извлекает параметры из HTTP-запроса (например, данные из полей формы) и передает их в качестве аргументов метода контроллера.
\end{itemize}

\textbf{Методы-обработчики запросов:}
\begin{itemize}
    \item public String index(Model model) - обрабатывает GET-запрос на "/". Добавляет в модель списки организаций и сотрудников, возвращает "index".
    \item public String showOrgEmployees(@RequestParam int id, Model model) - обрабатывает GET-запрос на "/showOrgEmployees". Загружает организацию и её сотрудников, возвращает "employeesList".
    \item public String addComOrg(...) / addNonComOrg(...) - обрабатывают POST-запросы на добавление коммерческой или некоммерческой организации.
    \item public String addEmp(...) - обрабатывает POST-запрос на добавление сотрудника с привязкой к организации.
    \item public String updateComOrg(...) / updateNonComOrg(...) - обрабатывают POST-запросы на обновление данных организаций.
    \item public String updateEmp(...) - обрабатывает POST-запрос на обновление данных сотрудника.
    \item public String deleteOrg(...) / deleteEmp(...) - обрабатывают POST-запросы на удаление по id.
\end{itemize}

После выполнения всех операций происходит перенаправление на главную страницу.

\subsection*{Взаимодействие с базой данных через Spring Data JPA и Hibernate}
\addcontentsline{toc}{subsection}{Взаимодействие с базой данных через Spring Data JPA и Hibernate}
Взаимодействие с базой данных PostgreSQL реализовано с помощью технологии ORM (Object-Relational Mapping), которую предоставляет Hibernate в качестве реализации стандарта JPA (Java Persistence API). Spring Data JPA дополнительно упрощает работу, избавляя от необходимости писать реализацию слоя доступа к данным.

Связь между Java-объектами и таблицами базы данных настраивается с помощью аннотаций:

\begin{itemize}
    \item \textbf{@Entity }: Указывает, что класс является сущностью и его объекты должны сохраняться в базе данных. Каждый экземпляр этого класса соответствует строке в таблице.
    \item \textbf{@Table(name = "...") }: Явно задаёт имя таблицы в БД, с которой связан данный класс.
    \item \textbf{@Id }: Помечает поле как первичный ключ таблицы.
    \item \textbf{@GeneratedValue }: Определяет стратегию генерации значения для первичного ключа. В данном проекте используется стратегия по умолчанию, которая для PostgreSQL означает использование последовательностей (sequences).
    \item \textbf{@Inheritance(strategy = InheritanceType.JOINED) }: Настраивает стратегию наследования. Стратегия `JOINED` означает, что для каждого класса в иерархии (базового и дочерних) создаётся своя таблица. Таблицы дочерних классов связаны с таблицей базового класса по внешнему ключу, которым является первичный ключ.
    \item \textbf{@OneToMany и @ManyToOne }: Определяют связь "один ко многим". Реализована между сущностями Organization и Employees: одна организация может иметь много сотрудников, но каждый сотрудник принадлежит только одной организации.

    В классе Organization связь описывается аннотацией @OneToMany. Атрибут `mappedBy = "organization"` указывает, что управление этой связью находится на стороне Employees в поле organization.

    \begin{lstlisting}
        @OneToMany(mappedBy = "organization", cascade = CascadeType.ALL, orphanRemoval = true)
        private List<Employees> employeesList = new ArrayList<>();
    \end{lstlisting}

    В классе \texttt{Employees} используется аннотация \texttt{@ManyToOne}.
    Аннотация \texttt{@JoinColumn(name = "org\_id")} указывает, что в таблице
    \texttt{employees} будет создан столбец \texttt{org\_id}, который будет
    внешним ключом, ссылающимся на первичный ключ таблицы \texttt{organizations}.
    \begin{lstlisting}
        @ManyToOne
        @JoinColumn(name = "org_id")
        private Organization organization;
    \end{lstlisting}

    \item \textbf{@Repository }: Аннотация, которая помечает интерфейс репозитория. Spring Data JPA сканирует такие интерфейсы и автоматически создает их реализации во время выполнения.
    \item \textbf{@Autowired }: Используется в контроллере для автоматического внедрения зависимостей, в данном случае — экземпляров репозиториев, что позволяет вызывать методы для работы с БД.
\end{itemize}

Таким образом, вместо написания SQL-запросов, разработчик оперирует объектами и вызывает методы репозитория, такие как `save()`, `findById()`, `findAll()`, а Hibernate генерирует и выполняет соответствующие SQL-запросы к базе данных.

\subsection*{Структура базы данных}
\addcontentsline{toc}{subsection}{Структура базы данных}

СУБД - PostgreSQL. Таблицы создаются автоматически Hibernate. Схема в третьей нормальной форме.

\textbf{Таблица organizations:}
\begin{itemize}
    \item id (SERIAL PRIMARY KEY)
    \item name (VARCHAR)
    \item inn (VARCHAR)
    \item employees\_count (INTEGER)
\end{itemize}

\textbf{Таблица comorganizations:}
\begin{itemize}
    \item id (INTEGER PRIMARY KEY, FOREIGN KEY \\REFERENCES organizations(id) ON DELETE CASCADE)
    \item profit (VARCHAR)
    \item business\_type (VARCHAR)
\end{itemize}

\textbf{Таблица noncomorganizations:}
\begin{itemize}
    \item id (INTEGER PRIMARY KEY, FOREIGN KEY \\REFERENCES organizations(id) ON DELETE CASCADE)
    \item purpose (TEXT)
    \item source (VARCHAR)
\end{itemize}

\textbf{Таблица employees:}
\begin{itemize}
    \item id (SERIAL PRIMARY KEY)
    \item name (VARCHAR)
    \item position (VARCHAR)
    \item org\_id (INTEGER, FOREIGN KEY REFERENCES organizations(id) ON DELETE SET NULL)
\end{itemize}

Связь между Organization и Employees - один ко многим. Для достижения третьей нормальной формы все неключевые атрибуты зависят только от первичного ключа.

\subsection*{Применение принципов ООП}
\addcontentsline{toc}{subsection}{Применение принципов ООП}

\textbf{Инкапсуляция:}
Все поля сущностей объявлены как private. Доступ к ним осуществляется через геттеры/сеттеры, которые генерируются Lombok.

\textbf{Наследование:}
Классы ComOrg и NonComOrg наследуют абстрактный класс Organization. Базовый класс содержит общие поля и методы, а также объявляет абстрактные методы report() и taxes(), которые реализуются в наследниках.

\textbf{Полиморфизм:}
При вызове методов report() и taxes() для каждого объекта выполняется соответствующий метод в зависимости от типа ComOrg или NonComOrg. При удалении организации каскадно удаляются связанные записи в дочерних таблицах.

\section*{Вывод}
\addcontentsline{toc}{section}{Вывод}

В ходе выполнения третьей лабораторной работы разработано веб-приложение на Java с использованием Spring Boot, Hibernate и PostgreSQL.

\begin{enumerate}
    \item Использован язык Java, сборщик Maven, СУБД PostgreSQL.
    \item Доступ к данным осуществляется через Hibernate  с помощью репозиториев, наследуемых CrudRepository.
    \item База данных содержит четыре таблицы, находящиеся в третьей нормальной форме. Реализована связь один ко многим между организациями и сотрудниками.
    \item Модель размечена аннотациями JPA используя Lombok.
    \item Веб интерфейс позволяет выполнять все CRUD-операции над организациями и сотрудниками.
\end{enumerate}

Приложение демонстрирует основные принципы ООП в контексте современного программирования на Java с использованием Spring.
