# Первое мнение
\\\\
Отличная задумка — для курсового проекта это реально, если сразу **сильно ограничить масштаб** и построить игру вокруг нескольких устойчивых систем, а не пытаться делать “всё и сразу”. Для Unity 6.4 самый удобный путь — разделить проект на: таймер суток, систему ресурсов, систему событий, систему действий игрока и пару мини-игр/активностей. Unity хорошо подходит для такого подхода: данные удобно хранить в `ScriptableObject`, а время/отложенные действия — через корутины. [docs.unity3d](https://docs.unity3d.com/6000.4/Documentation/Manual/class-ScriptableObject.html)

## Что делать первым

Сначала определи **ядро игры**: игрок просто переживает ночь до 8:00, а все механики нужны только чтобы мешать или помогать ему выжить. Тогда у тебя будет понятная главная петля: проходит время, происходят события, игрок выбирает реакцию, ресурсы меняются, игра либо продолжается, либо заканчивается. Это очень важно, потому что иначе проект расползётся.

Я бы предложил такой минимальный MVP:
- Одна комната.
- 4 ресурса: рассудок, деньги, голод, здоровье.
- Таймер с 00:00 до 08:00.
- 10–15 событий.
- 1 активность: крысиные бега.
- 1–2 “срочных” события с быстрым нажатием кнопки/мини-игрой.

## Архитектура проекта

Лучше делать не “всё в одном скрипте”, а по системам.

### 1. GameManager
Он хранит состояние игры:
- текущее время,
- запущена ли игра,
- победа/поражение,
- ссылка на ресурсы игрока,
- ссылка на менеджер событий.

Это будет центральная точка, откуда стартует ночь и где проверяется условие “дожил до 8:00”.

### 2. ResourceSystem
Отдельный класс или компонент, который хранит ресурсы:
- `sanity`
- `money`
- `hunger`
- `health`

И умеет:
- прибавлять/убавлять значения,
- ограничивать их диапазоном,
- проверять смерть при 0.

Хорошо, если у каждого ресурса будет максимум, например 100. Тогда балансировать станет проще.

### 3. TimeSystem
Он считает игровое время, например:
- 1 реальная секунда = 1 игровая минута,
- или 1 реальная секунда = 5 игровых минут.

Через этот же таймер можно:
- запускать события с определённой периодичностью,
- увеличивать голод,
- проверять, не пора ли спавнить новое событие.

Unity coroutines подходят для такого таймера и для отложенных действий. [docs.unity3d](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Coroutine.html)

### 4. EventSystem
Это самая важная часть. Тебе нужен не просто “рандомный вызов”, а структура событий:
- название,
- описание,
- тип,
- условия появления,
- последствия,
- варианты выбора,
- вес вероятности,
- кулдаун.

Для такого удобно использовать `ScriptableObject`, потому что события можно хранить как отдельные ассеты и быстро настраивать в инспекторе. [unity](https://unity.com/how-to/scriptableobjects-event-channels-game-code)

### 5. UISystem
Интерфейс должен показывать:
- 4 ресурса,
- время,
- текущее событие,
- кнопки выбора,
- предупреждения о срочных действиях,
- экран поражения/победы.

Для курсового я бы советовал обычный uGUI, потому что он проще и быстрее для runtime-UI в подобных задачах; Unity поддерживает и UI Toolkit, и uGUI, но uGUI часто удобнее для простого игрового интерфейса. [docs.unity3d](https://docs.unity3d.com/2021.3/Documentation/Manual/UIE-Transitioning-From-UGUI.html)

## Система событий

Твоя игра почти целиком держится на событиях. Хорошая модель — сделать каждое событие отдельным `ScriptableObject`.

### Что хранить в событии
Пример полей:
- `eventId`
- `title`
- `description`
- `eventType`
- `weight`
- `minTime`
- `maxTime`
- `cooldown`
- `choices`
- `isUrgent`
- `requiresMiniGame`

### Типы событий
Я бы разделил их так:
- Обычные выборы: друг просит в долг, кто-то пишет, сосед шумит.
- Срочные события: трубу прорвало, звонок в дверь, пожарная тревога.
- Пассивные события: потеря рассудка от голода, случайная находка денег.
- Активности: крысиные бега.

### Структура выбора
Каждый выбор должен содержать:
- текст кнопки,
- изменения ресурсов,
- вероятность дополнительного эффекта,
- переход в следующее состояние.

Пример:
- “Дать в долг” → `money -20`, `sanity +5`, `friendship +1`
- “Отказать” → `sanity -10`
- “Сказать, что нет денег” → без эффекта, но шанс повторного события ниже

## Как выбирать случайное событие

Нужен не просто `Random.Range`, а система весов.

### Простой вариант
1. Есть список всех событий.
2. Фильтруешь по времени и кулдауну.
3. Из оставшихся считаешь сумму весов.
4. Генерируешь число от 0 до суммы.
5. Выбираешь событие по накопленной вероятности.

Это легко реализовать и уже будет выглядеть как нормальная система.

### Важные ограничения
Чтобы игра не ломалась:
- одно и то же событие не должно повторяться слишком часто,
- срочные события не должны идти подряд,
- некоторые события должны зависеть от ресурсов.

Например:
- если денег мало, чаще приходит друг в долг;
- если здоровье низкое, чаще происходят события про усталость и болезни;
- если рассудок низкий, добавляются странные галлюцинации.

## Как делать срочные действия

Для событий типа “поломалась труба, нажми ключ несколько раз” нужен отдельный тип:
- event open,
- показывается UI,
- запускается таймер,
- игрок должен выполнить действие до конца таймера.

Это можно оформить как мини-состояние:
- `Normal`
- `ChoiceEvent`
- `QuickTimeEvent`
- `Minigame`
- `GameOver`

Тогда в любой момент игра знает, что сейчас происходит.

### Быстрое нажатие
Самый простой вариант:
- показываешь кнопку,
- игрок должен нажать её N раз за T секунд,
- каждый клик двигает прогресс,
- если не успел — штраф.

Это очень дёшево по времени разработки, но уже работает как полноценная механика.

## Крысиные бега

Это хорошая побочная механика, и её тоже лучше делать как маленькую автономную систему.

### Минимальный вариант
- Игрок ставит ставку.
- Запускается анимация/рандом.
- Случайно выбирается победитель.
- Выплачивается награда или проигрыш.

### Что важно
Не делай полноценный симулятор, если у тебя месяц.
Достаточно:
- экран ставки,
- 3–5 крыс,
- вероятность победы,
- короткая анимация,
- результат.

Это даст ощущение активности, но не заберёт весь срок.

## 2. Общая архитектура проекта

Для такого типа игр (управление ресурсами + события) лучше всего подходит **менеджерная архитектура с центральным GameManager** и системой событий на основе **ScriptableObject**.

### Основные компоненты (скрипты)

| Компонент | Назначение |
|-----------|------------|
| `GameManager` | Синглтон, контролирует состояние игры (игра идёт / пауза / победа / поражение), хранит ссылки на другие менеджеры. |
| `TimeManager` | Управляет игровым временем (часы, минуты), отсчитывает до 8:00, вызывает события по таймеру. |
| `ResourceManager` | Хранит текущие значения ресурсов, проверяет на 0, оповещает UI. |
| `EventManager` | Выбирает случайное событие из пула, запускает его, обрабатывает последствия. |
| `UIManager` | Обновляет все полоски ресурсов, часы, показывает окна событий. |
| `MinigameManager` | Управляет запуском мини-игр (крысиные бега, QTE с трубой). |
| `InputManager` | Обрабатывает клики по объектам в сцене (если есть взаимодействие с комнатой). |

### Данные событий – ScriptableObject

Создай `EventData` (ScriptableObject) с полями:
- `string title` – заголовок события.
- `string description` – описание.
- `Sprite icon` (опционально).
- `EventType type` – перечисление: TextChoice, QTE, TimedAction.
- `List<Choice> choices` – варианты ответов (текст + модификаторы ресурсов).
- Для QTE: `float timeLimit`, `int requiredClicks`.
- `float weight` – вероятность выпадения события (чем выше, тем чаще).
- `List<ResourceModifier> modifiers` – прямое изменение ресурсов при срабатывании.

### Ресурсы – `ResourceType` enum и класс

public enum ResourceType { Money, Sanity, Hunger, Health }

[System.Serializable]
public struct ResourceModifier
{
    public ResourceType type;

## 3. Детальное описание ключевых систем

### 3.1. GameManager и управление состоянием

Создай пустой GameObject `GameManager`, повесь скрипт. Он будет содержать ссылки на остальные менеджеры и статическое свойство `Instance`.

Основные состояния игры (можно через простой enum):
```csharp
public enum GameState { Playing, Paused, GameOver, Victory }
```

При старте игры (`Awake` или `Start`) инициализируются ресурсы стартовыми значениями, запускается `TimeManager`.

### 3.2. TimeManager (игровое время)

Реализуй через **Coroutine**.
Допустим, каждая минута реального времени = 1 игровой час (всего 8 часов до утра). Тогда общая длительность сессии ~8 минут.

```csharp
public class TimeManager : MonoBehaviour
{
    public float realSecondsPerGameHour = 60f; // 1 минута = 1 час
    public int startHour = 0; // 0:00 (полночь)
    public int endHour = 8;

    private int currentHour;
    private float timer;

    public event System.Action<int> OnHourChanged;
    public event System.Action OnVictory;

    void Start()
    {
        currentHour = startHour;
        StartCoroutine(TimeFlow());
    }

    IEnumerator TimeFlow()
    {
        while (currentHour < endHour)
        {
            yield return new WaitForSeconds(realSecondsPerGameHour);
            currentHour++;
            OnHourChanged?.Invoke(currentHour);
            // Возможно, пассивное уменьшение голода каждый час
        }
        OnVictory?.Invoke();
    }
}
```

**Примечание:** Можно добавить возможность ускорения времени (кнопка "Подождать час") для тестирования, но в финальной игре оставить только автоматическое течение.

### 3.3. ResourceManager

Хранит словарь `Dictionary<ResourceType, int>` текущих значений. Имеет методы `AddResource`, `RemoveResource`, которые вызывают проверку на 0 и обновление UI.

Пример проверки смерти:
```csharp
public void ModifyResource(ResourceType type, int delta)
{
    resources[type] = Mathf.Clamp(resources[type] + delta, 0, maxValues[type]);
    OnResourceUpdated?.Invoke(type, resources[type]);

    if (resources[type] <= 0)
        GameManager.Instance.GameOver(type);
}
```

### 3.4. EventManager и система событий

**Пул событий:** Создай папку `ScriptableObjects/Events`, создай несколько `EventData` через меню `Create -> Game/Event`.

`EventManager` будет хранить список `List<EventData> allEvents`. При вызове `TriggerRandomEvent()` выбирает случайное событие с учётом веса.

Выбор с весами простой:
```csharp
float totalWeight = 0;
foreach (var ev in allEvents) totalWeight += ev.weight;
float random = Random.Range(0, totalWeight);
foreach (var ev in allEvents)
{
    if (random < ev.weight) return ev;
    random -= ev.weight;
}
```

**Обработка события:**
- Если `type == TextChoice` → показать UI панель с текстом и кнопками вариантов.
- Если `type == QTE` → запустить мини-игру QTE (отдельный префаб).
- Если `type == TimedAction` → показать таймер и кнопку действия.

**Когда вызывать события?**
Добавь в `TimeManager` отдельный таймер на события: каждые `eventInterval` секунд реального времени (например, 30–45 секунд) вызывай `EventManager.TriggerRandomEvent()`.

### 3.5. Мини-игра: Крысиные бега

Сделай отдельный Canvas-префаб `RatRacePanel`, который активируется по клику на объект "Кровать" или кнопку UI.

Механика:
- У игрока есть деньги.
- Выбирает одну из трёх крыс (каждая со своим коэффициентом и скрытой вероятностью победы).
- Ставит сумму.
- Нажимает "Старт". Запускается анимация (например, полоски прогресса или простой таймер).

## 6. Полезные технические советы для Unity 6

- **Синглтоны:** Используй простой паттерн `public static GameManager Instance { get; private set; }` в `Awake`. Но помни про `DontDestroyOnLoad`, если сцена одна — не обязательно.
- **ScriptableObject события:** Очень удобно менять данные событий без кода, визуально редактировать в инспекторе.
- **События C# (`event Action`):** Для обновления UI подписывайся на изменения ресурсов, времени, чтобы не делать `Update` проверки.
- **UI Toolkit vs uGUI:** Для простоты используй классический uGUI (Canvas). Он проще для курсового.
- **Анимации:** Для крысиных бегов достаточно двигать `RectTransform` в корутине, не нужна сложная анимация.
- **Балансировка:** Создай `Debug` меню (например, кнопки для добавления ресурсов) для тестирования.

## 📊 4. Система ресурсов

public class Resource

```csharp
public class ResourceSystem : MonoBehaviour
{
    public List<Resource> resources;

    public void ChangeResource(string name, float amount)
    {
        var res = resources.Find(r => r.name == name);
        if (res == null) return;

        res.value += amount;
        res.value = Mathf.Clamp(res.value, 0, res.maxValue);

        if (res.value <= 0)
        {
            GameOver();
        }
    }
}
```

## ⚡ 8. QTE (быстрое действие)

Простой вариант:

* Появляется кнопка
* Надо нажать N раз за время

```csharp
public class QTE : MonoBehaviour
{
    public int requiredClicks = 10;
    private int currentClicks;
    public float timeLimit = 5f;

    void Update()
    {
        timeLimit -= Time.deltaTime;

        if (timeLimit <= 0)
            Fail();

        if (Input.GetMouseButtonDown(0))
        {
            currentClicks++;

            if (currentClicks >= requiredClicks)
                Success();
        }
    }
}
```
