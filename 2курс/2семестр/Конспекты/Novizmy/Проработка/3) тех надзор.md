## Технический надзор

Документ хороший по структуре, но есть несколько мест где подход создаст лишнюю работу или боль позже.

---

### ✅ Что оставить как есть

- `IInteractable` + Raycast — классика, работает, не трогай
- `ScriptableObject` для событий — правильно
- Разделение на Manager-классы — верно
- Greybox на неделю 1 — единственный правильный подход

---

### ⚠️ Проблемы и замены

**1. GameManager со States — замени на простой enum + события**

В документе предлагается класс GameManager который "контролирует всё" — это антипаттерн God Object. Через 2 недели он станет неуправляемым.

Вместо этого:

```csharp
// Простой глобальный стейт через статик-события
public static class GameState
{
    public static bool IsPlayerFrozen { get; private set; }

    public static event Action OnPlayerFrozen;
    public static event Action OnPlayerReleased;

    public static void FreezePlayer()
    {
        IsPlayerFrozen = true;
        Cursor.lockState = CursorLockMode.None;
        OnPlayerFrozen?.Invoke();
    }

    public static void ReleasePlayer()
    {
        IsPlayerFrozen = false;
        Cursor.lockState = CursorLockMode.Locked;
        OnPlayerReleased?.Invoke();
    }
}
```

PlayerController в `Update()` просто проверяет `if (GameState.IsPlayerFrozen) return;`. Никаких зависимостей между менеджерами.

**2. `alertVFX: ParticleSystem` прямо в ScriptableObject — не сработает**

ScriptableObject не может хранить ссылку на `ParticleSystem` из сцены, только на Prefab из проекта. Если хранить Prefab — нужен спавн и потом ручное уничтожение.

Проще:

```csharp
// В EventData храни только:
public GameObject alertVFXPrefab; // Prefab из Assets, не из сцены

// EventAnchor (на двери, трубе) сам знает свой VFX-объект
public class EventAnchor : MonoBehaviour
{
    [SerializeField] private ParticleSystem localVFX; // ссылка на VFX в сцене
    [SerializeField] private AudioSource    localAudio;

    public void Activate(EventData data)
    {
        localAudio.clip = data.alertSound;
        localAudio.Play();
        localVFX?.Play();
    }
}
```

Так каждый якорь сам знает свои эффекты — никакого спавна/деспавна.

**3. `timeToReact` в ScriptableObject + таймер в EventManager — архитектурная мина**

Если таймер живёт в EventManager, а UI живёт отдельно, а ресурсы в ResourceManager — получишь паутину вызовов. Через три недели не вспомнишь кто кого вызывает.

Реши это одним компонентом на якоре:

```csharp
public class ActiveEvent : MonoBehaviour
{
    private EventData _data;
    private float     _timer;

    public void Begin(EventData data)
    {
        _data  = data;
        _timer = data.timeToReact;
        GetComponent<Collider>().enabled = true; // включаем E-взаимодействие
    }

    private void Update()
    {
        _timer -= Time.deltaTime;
        if (_timer <= 0f) ApplyPenaltyAndEnd();
    }

    private void ApplyPenaltyAndEnd()
    {
        foreach (var c in _data.penaltyOnIgnore)
            ResourceManager.Instance.Modify(c.type, c.amount);
        Destroy(this); // убрали компонент — событие закрыто
    }
}
```

Вся логика события живёт рядом с событием, а не размазана по менеджерам.

**4. Крысиные бега — Coroutine со случайной скоростью каждый кадр**

В документе: "каждому кубику каждый кадр добавляется случайная скорость" — это даст дёрганое движение, не гонку.

```csharp
// Вместо этого — скорость назначается один раз при старте
private IEnumerator RunRace()
{
    // Каждой крысе — фиксированная скорость + маленький случайный буст раз в секунду
    float[] speeds = new float[3];
    for (int i = 0; i < 3; i++)
        speeds[i] = Random.Range(2f, 4f);

    while (!_raceFinished)
    {
        for (int i = 0; i < 3; i++)
        {
            _rats[i].position += Vector3.forward * speeds[i] * Time.deltaTime;

            // Маленький случайный буст раз в секунду — не каждый кадр
            if (Random.value < Time.deltaTime) // ~1 раз в секунду
                speeds[i] += Random.Range(-0.3f, 0.5f);
        }
        yield return null;
    }
}
```

**5. ResourceManager — добавь одну вещь которой нет в документе**

Падение ресурса до 0 сейчас вызывает мгновенный GameOver. Игрок не успеет понять что произошло. Добавь порог предупреждения:

```csharp
public void Modify(ResourceType type, float amount)
{
    _values[type] = Mathf.Clamp(_values[type] + amount, 0f, 100f);

    if (_values[type] <= 20f)
        OnResourceCritical?.Invoke(type); // UI пульсирует, звук тревоги

    if (_values[type] <= 0f)
        OnResourceDepleted?.Invoke(type); // GameOver
}
```
