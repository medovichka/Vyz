# ФАЗА 1: КОНЦЕПЦИЯ И ГЕЙМПЛЕЙНЫЙ ЦИКЛ (Core Loop)

**Суть игры:** Симулятор выживания в замкнутом 3D-пространстве от первого лица.  
**Цель:** Продержаться с 00:00 до 08:00.  
**Условие поражения:** Любой из 4 ресурсов (Здоровье, Рассудок, Голод, Деньги) падает до 0.

### Как это играется (Игровой цикл):

1. Ты ходишь по комнате (вид из глаз). Время неумолимо идет.
    
2. Голод и Рассудок медленно падают сами по себе.
    
3. Раздается триггер (звук/визуал): например, звонок телефона, стук в дверь, шум воды, писк крыс.
    
4. Ты должен найти источник в 3D-комнате, подойти и нажать "Взаимодействовать" (кнопка E).
    
5. При взаимодействии камера фиксируется, поверх экрана появляется UI с выбором или QTE-игра.
    
6. В свободное время ты можешь использовать объекты в комнате (съесть доширак со стола, лечь на кровать, поставить ставку на крыс), чтобы балансировать ресурсы.

# ФАЗА 2: ТЕХНИЧЕСКАЯ АРХИТЕКТУРА И СИСТЕМЫ

Так как игра в 3D, нам нужна система взаимодействия с объектами. Мы построим игру на **Менеджерах** и **Интерфейсах**.

### 1. Система передвижения и взаимодействия (Player Controller & Raycast)

Вместо кликов мышкой по 2D-экрану, игрок смотрит центром экрана.

- **Движение:** Стандартный Unity CharacterController (или готовый ассет First Person Controller, чтобы не тратить время).
    
- **Взаимодействие:** Из камеры каждый кадр пускается луч (Physics.Raycast). Если луч попадает в объект со скриптом, реализующим интерфейс IInteractable, на экране появляется подсказка "Нажми E".

```
// Любой объект, с которым можно взаимодействовать, будет иметь этот метод
public interface IInteractable 
{
    void Interact();
    string GetPromptText(); // Например: "Ответить на звонок", "Починить трубу"
}
```

### 2. GameManager (Управление состояниями)

Контролирует, что сейчас происходит. Если открыто меню события, игрок не должен ходить.

- **Состояния:** FreeWalk, InEventUI, InMinigame, GameOver, Victory.
    
- При переходе в InEventUI он блокирует мышь (освобождает курсор) и останавливает движение игрока.
    

### 3. TimeManager (Игровое время)

- Допустим, 1 реальная минута = 1 игровой час. Вся игра длится 8 минут.
    
- Скрипт переводит Time.deltaTime в игровые часы и минуты.
    
- Каждую игровую минуту вызывает событие OnMinutePassed (на него подпишутся голод и рассудок, чтобы понемногу отниматься).
    

### 4. ResourceManager (Статы)

Хранит Health, Hunger, Sanity, Money (от 0 до 100).

- Метод ModifyResource(ResourceType type, float amount).
    
- Проверка смерти: если значение <= 0, вызывает GameManager.GameOver().
    
- Отвечает за обновление 4 ползунков на экране (UI).

# ФАЗА 3: СИСТЕМА СОБЫТИЙ В 3D (САМОЕ ВАЖНОЕ)

В 2D события просто всплывают по центру. В 3D они должны быть привязаны к **точкам в комнате (Anchors)**.

### Шаг 1: Точки интереса (Event Anchors)

Расставь по комнате пустые GameObject'ы: DoorAnchor, PipeAnchor, PhoneAnchor, BedAnchor.

### Шаг 2: Данные события (ScriptableObject)

Создаем чертеж события в проекте.

```
public enum EventLocation { Door, Pipe, Phone, Bed, Anywhere }
public enum EventType { Choice, QTE }

[CreateAssetMenu(menuName = "DormSurvival/Event")]
public class EventData : ScriptableObject 
{
    public string eventId;
    public string title;
    public string description;
    public EventLocation location; // Где появится это событие
    public EventType type;
    public AudioClip alertSound; // Стук в дверь, звонок
    public ParticleSystem alertVFX; // Вода из трубы (опционально)
    
    public List<EventChoice> choices; // Варианты ответов
    public float timeToReact; // Если не подошел за 15 секунд - автоштраф
}
```

### Шаг 3: EventManager (Логика спавна)

Раз в 30–60 секунд менеджер:

1. Выбирает случайное событие (например, "Друг пришел за деньгами").
    
2. Смотрит его локацию -> EventLocation.Door.
    
3. Включает звук стука исходящий от двери (3D Audio).
    
4. Вешает на дверь коллайдер и скрипт IInteractable.
    
5. Если игрок подходит и жмет "Е", открывается UI-панель с текстом и выбором. В этот момент управление персонажем отключается, появляется курсор мыши.

# ФАЗА 4: МИНИ-ИГРЫ И АКТИВНОСТИ

### Активность 1: QTE "Починка трубы"

1. **Триггер:** Труба начинает шипеть, летят партиклы воды.
    
2. **Взаимодействие:** Жмем "Е" на трубу.
    
3. **Геймплей:** Появляется UI-таймер (например, 5 секунд) и огромная кнопка (или иконка ключа). Нужно нажать на неё ЛКМ 15 раз.
    
4. **Результат:**
    
    - Успел -> вода выключается, рассудок +10.
        
    - Не успел -> штраф: здоровье -20, лужа остается (можно сделать триггер зоны, который отнимает рассудок, пока стоишь в ней).
        

### Активность 2: Крысиные бега (Побочное занятие)

Чтобы не сойти с ума, ты можешь зарабатывать деньги.

1. **Где:** Под кроватью. Игрок подходит, жмет "Е". Камера перемещается под кровать (плавно или телепортом).
    
2. **UI:** Меню выбора из 3 крыс (разные шансы на победу, разные коэффициенты выигрыша) и поле ввода ставки.
    
3. **Визуал (Делай максимально просто!):** 3 вытянутых кубика (или 2D спрайта), которые просто двигаются вперед по оси Z. В корутине (Coroutine) каждому кубику каждый кадр добавляется случайная скорость.
    
4. Кто первый пересек линию — тот победил. Выдача денег или потеря ставки. Возврат камеры в обычное положение.

# ФАЗА 5: ПОДРОБНЫЙ ПЛАН РАЗРАБОТКИ НА 4 НЕДЕЛИ (ROADMAP)

Если ты будешь строго следовать этому плану, ты успеешь.

### Неделя 1: База (Каркас)

- **Сцена:** Собери серую комнату из кубов (Greybox). Пол, стены, кровать, стол, дверь, труба.
    
- **Игрок:** Настрой First Person Controller. Игрок может ходить и крутить камерой.
    
- **Интеракции:** Напиши скрипт Raycast, чтобы при наведении на объекты выводился текст ("Нажми Е").
    
- **UI и Статы:** Нарисуй 4 ползунка в Canvas. Напиши ResourceManager и свяжи их. Сделай кнопки для дебага (+10 еды, -10 хп).
    
- **Время:** Напиши TimeManager. Время идет, выводится на экран (00:00 -> 08:00), ресурсы сами потихоньку падают. При нуле ресурсов — экран Game Over.
    

### Неделя 2: События и скрипты

- **ScriptableObjects:** Создай класс EventData и настрой 5-7 событий через инспектор Unity (Стук в дверь, Сообщение в ВК (через комп на столе), Звонок мамы).
    
- **Интеграция в 3D:** Напиши EventManager. Заставь события "появляться" на нужных объектах (DoorAnchor и т.д.).
    
- **UI Выборов:** Сделай универсальное окно: Заголовок, Описание, 3 кнопки. Кнопки динамически подтягивают текст и последствия из EventData.
    
- **Состояния:** Настрой переключение управления. Когда смотришь в UI событий — мышка свободна, игрок не ходит. Когда нажал выбор — мышка прячется, игрок снова ходит.
    

### Неделя 3: Мини-игры и Наполнение

- **QTE Труба:** Создай UI для QTE. Сделай логику кликера. Подвяжи это к событию (EventLocation.Pipe). Настрой таймер провала.
    
- **Крысы:** Собери под кроватью мини-трек. Сделай UI ставок. Напиши простой скрипт гонки на корутинах (движение объектов по прямой со случайной скоростью).
    
- **Больше событий:** Доведи количество ивентов до 10-15 штук, чтобы игра не казалась пустой.
    

### Неделя 4: Графика, Звук, Полировка (ФИНАЛ)

- **Визуал:** Замени кубы на бесплатные ассеты (кровать из Asset Store, стол, дверь). Наложи текстуры. Настрой свет (одна тусклая лампочка в комнате даст шикарную атмосферу).
    
- **ЗВУК (Критически важно!):** Добавь AudioSource на дверь, телефон, трубу. Звуки шагов. Атмосферный гул (ambient). Звук тикающих часов. Звук скроет 80% недостатков графики.
    
- **Баланс:** Пройди игру сам раз 10. Убедись, что её реально пройти до 8 утра, но это не слишком легко.
    
- **Билд:** Собери проект в .exe, проверь на баги (не застревает ли курсор, не улетает ли игрок сквозь текстуры).

Не пытайся писать все системы разом. Открой Unity:

1. Создай пол (Plane) и стены.
    
2. Скачай любой "First Person Controller" (например, от Unity в Asset Store - Starter Assets - First Person Character Controller).
