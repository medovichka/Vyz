**Отличие mutex от семафора**

Мьютекс и семафор — это разные примитивы синхронизации (даже бинарный семафор не равен мьютексу):

1. **Концепция владения:** У мьютекса есть конкретный поток-владелец, и только он может его освободить. У семафора владельца нет — занять ресурс (уменьшить счетчик) может один поток, а освободить (увеличить счетчик) — совершенно другой.
2. **Назначение:** Мьютекс предназначен строго для взаимного исключения. Семафор используется для сигнализации между потоками и ограничения одновременного доступа к $N$ ресурсам.
3. **Приоритеты:** Поскольку ОС знает владельца мьютекса, она может применять механизм наследования приоритетов для защиты от инверсии приоритетов. С семафором это невозможно.
4. **Кратность:** Мьютекс имеет два состояния (захвачен / свободен). Семафор хранит целочисленный счетчик доступных ресурсов.

**Когда можно инициализировать семафор значением больше 1**

Когда есть ограниченное количество ($N$ штук) одинаковых ресурсов, к которым могут одновременно обращаться несколько потоков или процессов.
*Примеры:* пул соединений с базой данных (максимум 10 одновременных подключений), ограничение числа параллельных загрузок файлов или подсчет свободных слотов в очереди (задача Producer–Consumer).

**Свойства мьютекса и его особенности как объекта ядра**

**Свойства самого мьютекса:**

1. **Привязка к потоку (Ownership):** Жестко привязан к захватившему его потоку; освободить его может только владелец.
2. **Состояние:** Находится в одном из двух состояний — «свободен» (сигнальное) или «захвачен» (несигнальное).
3. **Рекурсивность (зависит от реализации):** Мьютексы ядра ОС или специальные типы позволяют потоку-владельцу захватывать себя повторно без блокировки, увеличивая внутренний счетчик захватов. Чтобы освободить мьютекс, поток должен вызвать освобождение столько же раз .

**Свойства, которые дает статус объекта ядра ОС:**

1. **Межпроцессная синхронизация:** Именованный мьютекс ядра виден разным процессам в системе.
2. **Обработка падения владельца (Abandoned state):** Если поток-владелец внезапно завершился (упал), не освободив мьютекс, ядро ОС фиксирует это, переводит мьютекс в состояние «брошен» и передает его следующему ожидающему потоку, предотвращая вечный deadlock.
3. **Управление на уровне ОС:** Поддержка системных дескрипторов (Handles), счетчика ссылок, прав безопасности (Security Descriptor) и ожидания по тайм-ауту.

**Что такое семафор**

Это примитив синхронизации, состоящий из неотрицательного **счетчика** и **очереди ожидания** потоков, поддерживающий две операции:

1. **Захват (`wait` / `acquire` / `P`):** Если счетчик больше `0`, он уменьшается на `1`, и поток сразу продолжает работу. Если счетчик равен `0`, поток блокируется и помещается в очередь ожидания, пока ресурс не освободится.
2. **Освобождение (`signal` / `release` / `V`):** Увеличивает счетчик на `1`. Если в очереди ожидания есть заблокированные потоки, ОС будит один из них для захвата ресурса.
